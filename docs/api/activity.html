list

GET /v1/activities

Operation ID: listActivities.

Authentication: bearer token (Bearer-Auth).

Parameters

| Parameter | In | Type | Required | Description | | --- | --- | --- | --- | | start | query | string | No | The token for the page of results you want to return. Responses contain a next property. Use this property as the start value to return the next page of results. | | type | query | enum: add_relationship, anon_merge, attempted_action, attempted_email, attempted_in_app, attempted_push, ... | No | The type of activity you want to search for. Types with _o:&lt;object_type_id&gt; are for objects and types with _r:&lt;object_type_id&gt; are for relationships. | | name | query | string | No | The name of the event or attribute you want to return. | | deleted | query | boolean | No | If true, return results for deleted people. | | customer_id | query | string | No | The identifier of the person you want to look up. By default, this is a person's id. You can use the id_type parameter to look up a person by email, phone, or cio_id. If you use a person's cio_id, you must prefix the value with cio_ when using it to find or reference a person (that is cio_03000010 for a cio_id value of 03000010). | | id_type | query | enum: id, email, phone, cio_id | No | The type of customer_id you want to use to reference a person. If you don't provide this parameter, we assume that the customer_id in your request is a person's id. You can use email and phone only if they're enabled as identifiers in your workspace settings; otherwise the request returns 400. Reference phone values in E.164 format, like +14155552671, and URL-encode the leading + as %2B. | | limit | query | integer | No | The maximum number of results you want to retrieve per page. |

Responses

200: Returns an array of activities

application/json

Property Type Required Description
activities array of object No
activities[].customer_id string,null No The ID of a customer profile, analogous to a "person" in the UI. If your workspace supports multiple identifiers (email and ID), this value can be null.
activities[].customer_identifiers object No Identifiers for the person in a response, id, cio_id, and email. Unset id or email values are null. We recommend this object over the less descriptive customer_id. This object doesn't include phone, even if your workspace uses phone numbers as an identifier; look for the person's phone attribute instead.
activities[].customer_identifiers.cio_id string Yes A unique identifier set by Customer.io, used to reference a person if you want to update their identifiers.
activities[].customer_identifiers.email string,null (email) Yes A person's email address, if set.
activities[].customer_identifiers.id string,null Yes A person's unique ID, if set. This is the same as the customer_id if present.
activities[].data object or object No
activities[].delivery_id string No The message ID.
activities[].delivery_type enum: ios, android, email, phone No The recipient device, if applicable.
activities[].id string No The identifier for the action.
activities[].name string No The name of the event, for event and screen activities.
activities[].timestamp integer (unix timestamp) No The date and time when the action occurred.
