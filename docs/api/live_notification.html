POST /v1/live_notifications/end

Operation ID: endLiveNotification.

Authentication: bearer token (Bearer-Auth).

Request body

application/json

Property Type Required Description
attributes object No Static activity fields, for renderers that need them alongside the content state.
content_state object or object or object No The final content state to show before the activity ends. Defaults to the last state you sent. The content state's shape depends on the activity's notification_type. For iOS or a free form Android activity, pick the free form variant. For other Android notification types, pick the matching variant below.
deep_link string No A link to open when the person taps the activity.
instance_id string Yes The activity's instance ID (ULID), returned when you started it.
push_payload object No The alert to accompany the end event. Optional whether Customer.io delivers directly through APNs or relays through Firebase Cloud Messaging (FCM). If you include an alert, provide both its title and body.
push_payload.alert object No
push_payload.alert.body string Yes The alert body.
push_payload.alert.sound string No The sound to play with the end event.
push_payload.alert.title string Yes The alert title.

Responses

200: The end event was queued

application/json

Property Type Required Description
instance_id string No The activity's instance ID.
400: The request was malformed, instance_id isn't a valid ULID, or a push_payload.alert was missing a title or body
404: Live notifications aren't enabled for this workspace

POST /v1/live_notifications/start

Operation ID: startLiveNotification.

Authentication: bearer token (Bearer-Auth).

Request body

application/json

Property Type Required Description
app_identifier string No The identifier of the app to start the activity on, a bundle ID on iOS or a package name on Android. This only matters when your workspace has multiple apps: set it to target a device belonging to that app, or omit it to target the workspace's default app. Workspaces without multiple apps ignore this field. If you provide a value that doesn't match an app in your workspace, the request fails with a 400.
attributes object or object or object Yes Static fields used to create the activity, an order number, a flight's origin and destination, or the teams in a match. On iOS they can't change after start. On Android, include the static fields your renderer needs on update and end calls too, because the SDK renders from a merged payload. The shape depends on your notification_type: pick the free form variant for iOS or a free form Android activity, or the matching bundled-template variant below. Template fields are documented for iOS and Android.
content_state object or object or object Yes The initial dynamic content for the activity, the status, score, or ETA the device renders. Send the complete state on every call; partial updates aren't supported. The shape depends on your notification_type: pick the free form variant for iOS or a free form Android activity, or the matching bundled-template variant below. Date fields are epoch seconds.
deep_link string No A link to open when the person taps the activity.
device_id string No The device token identifying the device to start the activity on.
expiration integer No A unix timestamp (in seconds) for when the activity should expire. Must be no more than 6 hours in the future, values outside the range between now and that 6-hour maximum are rejected with a 400. If you omit it (or pass 0), the activity expires 6 hours after it starts.
identifiers object Yes Identifies the profile you want to start the activity for. You must provide exactly one of id, email, phone, or internal (our internal identifier, cio_ followed by an alphanumeric string). You cannot target anonymous profiles.
identifiers.email string No The profile's email address.
identifiers.id string No The profile's id attribute.
identifiers.internal string No Our internal identifier for the profile, prefixed with cio_.
identifiers.phone string No The profile's phone number.
notification_type string Yes The reverse-DNS identifier of the activity type, like io.customer.livenotifications.segments. Must match a type your app registered with the SDK.
platform enum: ios, android No The device platform.
push_payload object No The alert shown when the activity starts. Required for iOS.
push_payload.alert object No
push_payload.alert.body string Yes The alert body.
push_payload.alert.sound string No The sound to play when the activity starts.
push_payload.alert.title string Yes The alert title.

Responses

200: The activity was queued. Returns the instance ID for the new activity

application/json

Property Type Required Description
instance_id string No The unique identifier (ULID) for the new activity instance. Use it to update, end, or check the status of the activity.
400: The request was malformed, a missing required field, an invalid platform, more or fewer than one identifier, or a missing iOS alert
404: Live notifications aren't enabled for this workspace
